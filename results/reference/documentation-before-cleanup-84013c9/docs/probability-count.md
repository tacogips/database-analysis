# 整数主キーのセル標本による件数推定

この方法は、データ内容を読まずに数%幅の信頼区間を計算する検証中の候補です。実装はCompose専用の [samplinglib.py](../bench/samplinglib.py) と [sampling_bounds.py](../bench/sampling_bounds.py)、現行の代表観測は[校正§4](table-count-calibration.md#4-代表fixtureと条件付き標本の位置付け)です。98番は過去研究です。本番用の配布クライアントではありません。

適用前に[実務ガイド§1・3・4](table-count-guideline.md)の承認済み取得先・準備作業の予算・資源分離/上限・所有処理の取消確認・回復監視を満たします。本書の数学的条件だけで本番実行を許可しません。

## 適用条件と取得時点

- InnoDBの単一整数主キーが必要です。現在の実装は列名idを対象とし、型・エンジンを確認します。SQL上のUUID・文字列・二進型・複合キー等には適用しません。TDEや暗号由来の値でもSQL上の一意整数idであれば候補であり、復号鍵や平文の意味は入力しません。
- MIN/MAXから最後の標本まで同じREPEATABLE READスナップショットを使います。対象表へアクセスしてMDLを得た後にスキーマを再確認します。各セルのCOUNTは全件数の推定のための内部範囲で、業務上の条件ではありません。
- キー空間の固定幅セルを一様・復元抽出します。繰り返し同じセルを引くこともあります。層ごとに標本を配分する層化実装ではありません。
- クエリごとの制限、全体予算、監視、終了確認が必要です。長いスナップショットはMDLとundoを保持し、レプリカでもDDL適用を待たせ得ます。primaryの既定手順としては案内しません。

## 推定と信頼区間

セル数をB、整数キー幅をW、選んだセルの件数をCとすると、一意キーにより0≤C≤Wです。一様復元抽出したnセルの平均にBを掛けて全体を推定します。末尾の短いセルも同じ確率で選びます。値の意味・暗号文・復号鍵は推定式へ入力しません。

境界は [Maurer and Pontil 2009](https://www.cs.mcgill.ca/~colt2009/papers/012.pdf) のTheorem 1と4を使います【文書】。Theorem 4は両側へ適用します。判定時点kへの誤差確率をαk=α/(k(k+1))とし、さらに半分ずつをHoeffdingとempirical Bernsteinへ配分して区間を交差させます【導出】。すべての判定への配分合計がα以下なので、宣言した途中停止でも全体の信頼度を保ちます。観測分散が0でも、未知の密集域を見落とした不確かさは0にしません。

実装は整数・Decimalで集計し、区間端を外側へ丸め、キー領域から分かる上限で切ります。相対誤差は推定値に対する幅だけでなく、未知の真値の下側区間端を使って保守的に評価します。信頼区間が狭まるかは標本結果から判断し、未知のデータを密だと事前に仮定しません。

信頼度は、規定した独立・一様抽出と固定スナップショットのモデルに対する確率的な性質です。今回の値が必ずその誤差内にあるという絶対保証ではありません。固定seedの少数の実験だけで被覆確率を実証したとは扱いません。本番実装へ移す場合は公開された固定seedを使い回さず、対象状態と独立に選んだ新しい乱数入力を使います。固定seedはラボの再現用です。複数テーブル・シャード・再実行を含む結果全体の信頼度が必要なら、全対象の判定へ配分するαを先に決めます。

## 結果の判定と負荷予算

`accuracyStatus`、`budgetStatus`、`cleanupStatus`は別々です。`target_reached`でも予算超過や後始末失敗があれば運用上の成功ではありません。`attempted_draws`、`completed_draws`、`last_valid_checkpoint_draws`を分け、最後の区間がどの標本数に対応するかを保存します。宣言していない停止時点で勝手に区間を再計算しません。

全体時間は、用意済み接続への最初のSQLからROLLBACKまでを計ります。接続準備は呼出し側の別予算です。問い合わせ前後と終了時に予算を確認しますが、これはクエリ境界での協調的な制限です。厳密な時刻でサーバー処理を終了させる機構ではありません。タイムアウトや接続断の後には終了確認も必要です。

`precision_not_reached`、`budget_exhausted`、`query_failed`、`cleanup_failed`、`inapplicable`を、精度を満たした全件数として返しません。空標本を空表と見なしません。完全な空表は、スナップショット内のMIN/MAXで別に判定します。

ラボの幅・標本数・時間値は [実験結果](../results/reference/20261107-observations/requested_probability_sampling.json) と実装に記録しています。安全値ではありません。疎な領域では多数のランダム範囲COUNTでも区間が広いままで、全件COUNTより高価になり得ます。読み取ったキー件数の上限は、実I/O量・MVCCの処理量の上限ではありません。

## 計測から言える範囲

現行の[校正資料](table-count-calibration.md#2-観測した最大最小誤差と条件)が、固定snapshotの元JSONを使い、旧観測と新しい白紙allの精度・費用・採否を区別します。密な表の誤差0%、極端な空隙の未採用推定0と誤差100%、丸めた0を混同しません。疎な領域では全件COUNTより高価になり得ます。

[新105静的観測](../results/reference/review-20261107T155750Z-26743/results/requested_accuracy_cost_frontier.json)は目標到達75・精度未達30、[新100列48arm](../results/reference/review-20261107T155750Z-26743/results/requested_accuracy_service_100.json)は3%・10%目標それぞれ12到達でした。COUNTの時間上限を完了時間として順位付けせず、接続準備とSQL〜ROLLBACKの予算も分けます。固定seedの反復は将来の被覆率の実証ではありません。

先行COUNT・実行順・host/VMキャッシュは未制御です。短い実メソッド窓とbaseline/trial/recoveryの窓を混ぜず、疎・未完了到着を除いてSLOを合格にしません。実験完了・精度・サービス予算・後始末は別判定です。5%サービスarm、1億行80列TDE、実アプリ暗号性能は未計測です。

[所有者proof](../results/reviews/final-all-proof.json)は縮小範囲の白紙all・意味/source・整合・後始末の証明で、統合後の文書に対する最終Sol 2役の受入れではありません。[旧詳細](table-count-evidence.md)や修正提出は履歴として保持します。
